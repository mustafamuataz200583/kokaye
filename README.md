# KOKAYE | كوكاية — المتجر الإلكتروني

متجر حقيقي: الطلبات تنحفظ بقاعدة بيانات Supabase (PostgreSQL)، ومعاه لوحة تحكم خاصة لصاحب المتجر.

**التقنيات:** Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · Motion · Supabase (Postgres + Auth + Storage) · Vercel

---

## 1) شنو موجود

| الواجهة | لوحة التحكم (`/admin`) |
|---|---|
| الرئيسية، المنيو مع التصنيفات، صفحة المنتج | تسجيل دخول آمن عبر Supabase Auth + جدول `admin_users` |
| سلة جانبية + صفحة سلة (تنحفظ بالمتصفح) | إحصائيات: جديدة، قيد التحضير، مكتملة، ملغية، مبيعات المكتملة، الأكثر طلباً |
| إكمال الطلب بدون حساب (7 حقول) | الطلبات: بحث، فلترة حسب الحالة، تفاصيل، تغيير الحالة، أجور التوصيل، ملاحظات داخلية، اتصال/واتساب |
| صفحة نجاح الطلب (نسخ الرقم + إرسال الملخص على واتساب) | المنتجات: إضافة، تعديل، سعر، صورة (رفع)، وصف، تصنيف، إخفاء، نفدت الكمية، مميز، ترتيب، خيارات إضافية |
| تتبع الطلب (رقم الطلب + رقم الهاتف) | الإعدادات: الهاتف، واتساب، أوقات الاستقبال، فتح/غلق الطلبات، نصوص التوصيل، السوشيال، الخصوصية والشروط |
| من نحن، تواصل ويانا، الخصوصية، الشروط، 404 | تحديث تلقائي لقائمة الطلبات كل 30 ثانية |

## 2) الأمان (باختصار)

- **الأسعار من القاعدة فقط.** المتصفح يرسل رقم المنتج والكمية بس. الدالة `place_order` تسعّر وتتحقق من التوفر وحالة المتجر، وتحفظ لقطة من الاسم والسعر وقت الشراء.
- **ما يتكرر الطلب.** كل محاولة طلب إلها مفتاح `idempotency_key` فريد، ومعاه قفل بقاعدة البيانات. حتى لو انقطع النت أو انضغط الزر مرتين، يبقى طلب واحد (تم اختباره).
- **RLS مفعّل على كل الجداول بدون أي policy.** وكل الصلاحيات مسحوبة من `anon` و`authenticated`. يعني المفتاح العام (anon key) ما يقرأ ولا يكتب أي شي.
- **كل الوصول للبيانات من السيرفر فقط.** يتم عبر `DATABASE_URL`، والملف مقفول بـ `server-only`. مفتاح الخدمة يُستخدم فقط لرفع الصور، وما يوصل للمتصفح.
- **صلاحيات الأدمن تنفحص بكل صفحة وكل action.** الفحص يصير بالسيرفر عبر `getUser()` + جدول `admin_users`. ماكو كلمة مرور داخل الكود.
- **أرقام الطلبات عشوائية** بشكل `KK-XXXXXX`. التتبع يحتاج الرقم ورقم الهاتف سوية، ومحدود بـ 10 محاولات كل 10 دقائق.
- **حماية إضافية:**
  - حدود محاولات للطلب وتسجيل الدخول.
  - رفض الطلبات القادمة من مواقع ثانية.
  - حقل فخ (honeypot) ضد البوتات.
  - فحص نوع الصورة من محتواها الفعلي.
  - هيدرات أمان، وصفحات الأدمن `noindex`.

## 3) التشغيل والنشر — خطوة بخطوة

### أ. Supabase
> الـ migrations تنشغل بالترتيب: `0001_init.sql` ثم `0002_gallery_and_photos.sql` ثم `0003_menu_cleanup.sql` ثم `seed.sql`.
> **إذا عندك قاعدة منصوبة من نسخة سابقة:** شغّل بس الملفات الجديدة (`0002` إذا ما شغلته، ثم `0003`).

1. سوّ مشروع جديد على [supabase.com](https://supabase.com). يفضل تختار منطقة قريبة، مثل Frankfurt (`eu-central-1`).
2. افتح **SQL Editor** وشغّل الملفات بالترتيب: `supabase/migrations/0001_init.sql`، ثم `0002_gallery_and_photos.sql`، ثم `0003_menu_cleanup.sql`، ثم `supabase/seed.sql` (المنيو والأسعار والصور). أو نفّذ `DATABASE_URL=... npm run db:migrate -- --seed`.
3. **Authentication → Users → Add user**: سوّ حساب صاحب المتجر (بريد + كلمة مرور قوية) وفعّل Auto Confirm.
4. اعطيه صلاحية الأدمن. شغّل بالـ SQL Editor:
   ```sql
   insert into public.admin_users (user_id, email)
   select id, email from auth.users where email = 'owner@example.com';
   ```
   أو من جهازك: `DATABASE_URL=... npm run admin:add -- owner@example.com`
5. **Authentication → Sign In / Providers**: طفّي "Allow new users to sign up". الحسابات تنضاف يدوياً فقط.
6. **Storage**: الـ migration ينشئ bucket باسم `product-images` (عام للقراءة). إذا ما انخلق، سوّه يدوياً: Public، الحد 5MB، الصيغ jpeg/png/webp.

### ب. متغيرات البيئة
انسخ `.env.example` إلى `.env.local` (محلياً) أو حطها بـ Vercel → Settings → Environment Variables:

| المتغير | من وين | عام؟ |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | دومين الموقع | نعم |
| `NEXT_PUBLIC_SUPABASE_URL` | Project Settings → API | نعم |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Project Settings → API (anon / publishable) | نعم (ما يقرأ أي بيانات) |
| `SUPABASE_SERVICE_ROLE_KEY` | Project Settings → API (service_role / secret) | **سري** |
| `DATABASE_URL` | Connect → **Transaction pooler** (port 6543) | **سري** |
| `RATE_LIMIT_SALT` | أي نص عشوائي طويل | **سري** |

### ج. محلياً
```bash
npm install
npm run dev        # http://localhost:3000   — لوحة التحكم: /admin
```

### د. Vercel
1. ارفع المشروع على GitHub واربطه بـ Vercel.
2. حط المتغيرات (الخطوة ب).
3. Deploy. **مهم:** البناء يقرأ المنيو من القاعدة، فلازم `DATABASE_URL` يكون مضبوط قبل أول نشر.
4. يفضل تختار Function Region قريب من منطقة Supabase (Settings → Functions).

## 4) قرارات تحتاج مراجعتك

1. **المنيو الحالي (6 منتجات، كلها بصور حقيقية):**

   | المنتج | السعر |
   |---|---|
   | Classic Cookies | 2,500 د.ع |
   | Dark Chocolate Cookies (صورتين) | 2,500 د.ع |
   | Pistachio Cookies | 2,500 د.ع |
   | Lotus Cookies | 2,500 د.ع |
   | Red Velvet Cookies | 2,500 د.ع |
   | Scoop Cookies | 7,000 د.ع |

   - **انحذفت نهائياً:** Molten Cookie وTiramisu Cookies، وKinder Cookies وMini Cookies لأن ماكو إلهن صور. الطلبات القديمة اللي بيها هالمنتجات تبقى محفوظة بأسمائها وأسعارها.
   - **أسعار Lotus وRed Velvet:** توحدت مع سعر القطعة المماثلة (2,500). أسماء المنتجين ووصفهما المختصر اقتراح مني.
   - **قسم "لحظة مشاركة" بالرئيسية:** صار يعرض Scoop Cookies بدل Mini.
   - **الصور:** شلت الخلفية الخوخية من صورك، وحطيت كل منتج على خلفية رملية موحدة (`#F1E5D3`) مع الحفاظ على الظل الطبيعي، وبنفس الحجم والتوسيط داخل إطار 4:5. الإطارات بالموقع بنفس اللون، فالصور تندمج بدون حواف.
   - **إذا أضفت منتج جديد:** يفضل تكون صورته بنفس الأسلوب (منتج واحد، إضاءة ناعمة، خلفية سادة).
2. **الأوصاف المختصرة** كتبتها عامة وبدون أي ادعاء عن الحشوات أو الأوزان. الوزن وعدد القطع والحشوة تظهر فقط إذا انكتبت من لوحة التحكم.
3. **أسماء المنتجات** بقت مثل ما أعطيتها (إنكليزي). تقدر تضيف اسم عربي لكل منتج.
4. **الخطوط.**
   - Tajarib **Bold** لكل العناوين الرئيسية والفرعية، وCormorant Bold لأسماء المنتجات: ترخيصه يسمح بالمواقع، بس يذكر أن *تضمين ملف الخط* قد يحتاج مراجعة "حرف".
   - Thmanyah Sans للنصوص.
   - Cormorant Garamond (ترخيص OFL مجاني) للأسماء الإنكليزية، حتى تنسجم ويا شعار KOKAYE.

   **تأكد من حق التضمين على الويب لخطي تجارب وثمانية قبل النشر.**
5. **الخصوصية والشروط** نص مبدئي (مسودة) بدون ادعاءات قانونية. راجعه وعدّله من الإعدادات.
6. **الدفع.** ما ذكرت طريقة دفع، فما كتبت عنها شي. إذا الدفع عند الاستلام، اضفها لنص التوصيل أو الشروط.
7. **التصنيفات** الثلاث مقترحة: Classic، Special Flavors، Sharing & Desserts. تقدر تغير تصنيف أي منتج من لوحة التحكم.

## 5) الاختبار
اختبار شامل تلقائي (`test/e2e.cjs`): **78/78 نجح** على بناء الإنتاج، بقاعدة PostgreSQL 16 حقيقية. يغطي:
- كل الصفحات والروابط، وعدم وجود تمرير أفقي على iPhone.
- الفلاتر، والإضافة للسلة، والعداد، وبقاء السلة بعد التحديث، وتحديث الأسعار مباشرة.
- التحقق من الحقول، والأرقام العربية بالهاتف.
- حفظ الطلب بأسعار القاعدة.
- انقطاع النت بعد الإرسال ثم إعادة المحاولة: طلب واحد فقط.
- الضغط المزدوج المتزامن.
- تجاهل السعر المرسل من المتصفح.
- رفض الطلبات من مواقع ثانية.
- المنتجات النافدة.
- غلق المتجر.
- التتبع، ورفض الهاتف الخطأ، وحماية التخمين.
- دخول الأدمن، ورفض حساب غير أدمن، وتسجيل الخروج.
- تغيير الحالة وظهورها للزبون.
- أجور التوصيل.
- رفع صورة وتعديل سعر وظهوره بالمتجر.
- الخيارات الإضافية.
- الإعدادات.
- المنيو الجديد: 6 منتجات، والمنتجات المحذوفة ترجع 404، وماكو صور ناقصة.
- معرض الصور، ومنع إظهار منتج بدون سعر.
- عدم وجود أخطاء بالـ console.

> ملاحظة صريحة: الاختبار صار على PostgreSQL محلي بنفس أدوار Supabase، وعلى بديل محلي بسيط لـ Supabase Auth/Storage (`test/mock-supabase.mjs`). **ما اتصلت بمشروع Supabase حقيقي لأن ما عندي مفاتيحه.** بعد ما تربط مشروعك، جرّب: طلب من الموبايل، ثم دخول الأدمن، ثم رفع صورة.

تشغيل الاختبار محلياً: Postgres على 5432، ثم شغّل `test/local-supabase-shim.sql` و الـ migration و الـ seed، ثم `node test/mock-supabase.mjs`، ثم `npm run build && npm start`، وبعدها `node test/e2e.cjs`.
